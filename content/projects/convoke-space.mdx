Convoke.space is both a personal site and the system that publishes it. The
site is the visible half; the operating model is the part that took the design
work.

## The constraint

The requirement was not "a personal website". It was: *this has to be
maintainable for years, from a phone, without a development machine, by
whichever AI assistant happens to be available.*

Every architectural decision below follows from that sentence.

## How it is built

- **Next.js on the App Router**, TypeScript throughout, Tailwind CSS for
  styling. Content is MDX on disk, compiled at build time.
- **No database, no authentication, no CMS.** Content is files in Git. Adding a
  post is a pull request. This is the entire content pipeline, and it is enough.
- **No web fonts and no client-side analytics.** Typography uses the operating
  system's own serif and sans stacks. Nothing is loaded from a third party, so
  there is nothing to break, nothing to consent to, and nothing to slow the
  first paint.
- **A hand-written frontmatter validator** rather than a schema library.
  Roughly a hundred lines, dependency-free, and it fails the build with a
  message precise enough to fix the file without reading the validator.

The dependency list is deliberately short. Every package added is a package
someone has to keep current for as long as the site exists.

## How it is operated

Two repositories. `convoke-space/public` is the application and everything
published; `convoke-space/private` holds drafts and working material. Production
builds from the public repository alone — no cross-repository clone, no build
token, no runtime fetch. Publication is an explicit promotion step with a
sanitization checklist, not a synchronisation.

Work happens on task branches owned by exactly one agent at a time. Every change
goes through a pull request with automated validation — lint, typecheck, tests,
production build — and a human merges. Deployment is automatic from `main`.

The repositories carry their own operating instructions in `AGENTS.md`, so a
fresh session from any vendor can read them and behave correctly without being
re-briefed.

## Status

Live, and intentionally small. The architecture leaves room for a database,
authentication, or a registration system if a real requirement ever appears —
but none of those exist today, and none of them are scaffolded in advance.
